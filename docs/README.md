# Documentation Map

This folder contains the planning and delivery documents for the Incident
Management System: an AI-enhanced incident reporting and resolution platform.

## Reading Order

Read the files in this order:

1. `docs/product-scope.md`
2. `docs/development-roadmap.md`
3. `docs/technical-architecture.md`
4. `docs/demo-flow.md`
5. `docs/uipath-integration.md`

## Documents

- [product-scope.md](product-scope.md)
  Defines the product scope, user roles, required capabilities, acceptance
  criteria, and current feature status.

- [development-roadmap.md](development-roadmap.md)
  Lists the remaining planned work and known gaps.

- [technical-architecture.md](technical-architecture.md)
  Describes the current and target architecture across frontend, backend,
  database, AI, and UiPath.

- [demo-flow.md](demo-flow.md)
  End-to-end demo script and screenshot guide.

- [uipath-integration.md](uipath-integration.md)
  Operational contract for the UiPath bridge and current bot baseline.

## Documentation Rules

- Do not claim a capability is complete unless it can be demonstrated in UI, API,
  UiPath Studio, logs, or screenshots.
- Keep language focused on incident reporting and resolution.
- Update roadmap and architecture notes when implementation status changes.
- Keep demo scripts aligned with real file names, real endpoints, and real screenshots.
